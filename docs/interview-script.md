# Pair-Programming Script

## Opening

“I’ll start by restating the problem and clarifying the success criteria before coding. My goal is to get a working MVP first, then improve polish and accessibility if time allows.”

## AI usage framing

“I may use AI for bounded tasks like filling a planning template, checking edge cases, reviewing accessibility, or drafting a commit message. I’ll keep control of the implementation and review anything it suggests before applying it.”

## Clarifying the problem

Useful questions:

- Who is the primary user?
- What is the core action they need to complete?
- What should be working by the end?
- Are there required data fields or states?
- Should I optimize for fidelity, functionality, accessibility, or speed?
- Are there any constraints around dependencies or browser support?

## Scope control

“I’m going to treat this as the MVP: first make the core interaction work, then come back for responsive styling, accessibility, and polish.”

“I’m going to defer that as a production-hardening concern unless we have time.”

## Collaboration

“Does this slice match what you expected, or would you rather I prioritize a different part of the experience?”

“I see two options here. I’ll explain the tradeoff and choose the simpler path unless you want me to go deeper.”

## When stuck

“I’m going to pause and narrow the problem. The quickest recovery path is to isolate whether this is data, rendering, state, or CSS.”

## Closing recap

“At this point, the solution does X and Y. I validated it by checking Z. The main tradeoffs are A and B. If this were moving toward production, I would next improve C, D, and E.”
